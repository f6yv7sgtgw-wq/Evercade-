# Project Evercade 0.9.4

## Ziel

Kleinanzeigen wird nicht mehr nur als optischer Zusatz geführt. Die GenericParser-Ergebnisse werden in dieselben Laufzeitdaten geschrieben, die auch die bestehende Evercade-Anwendung verwendet.

## Integration

- Worker: `https://genericparser.f6yv7sgtgw.workers.dev`
- Vertrag: `generic-parser-module-v1`
- Endpunkte: `/api/version`, `/api/module/v1/capabilities`, `/api/module/v1/search`
- keine Token-Authentifizierung
- Kleinanzeigen wird in `state.background.sourceStatus` geführt
- Treffer werden in `state.monitor.observations` übernommen
- jeder Server-Snapshot wird anschließend mit dem lokalen Kleinanzeigen-Status zusammengeführt
- `renderAlerts()` berechnet die sichtbare Anzahl aus der tatsächlichen Statusliste
- `runBackgroundScan()` startet nach dem bestehenden Serverlauf zusätzlich die GenericParser-Prüfung
- interaktive Deal-Suche prüft bis zu vier Pakete
- täglicher Lauf prüft je fehlender Cartridge zunächst ein Paket

## Konsistenz

Der GitHub-Pages-Workflow prüft vor der Veröffentlichung:

- JavaScript-Syntax
- Version 0.9.4 in Manifest und Metadaten
- feste Worker-URL
- Vertrags- und Suchendpunkt
- gemeinsame Quellenstatus-Datenstruktur
- gemeinsame Monitor-Datenstruktur
- Hooks für Server-Snapshot, Alarmdarstellung und Hintergrundscan
- Entfernung der früheren parallelen Kleinanzeigen-Skripte aus dem veröffentlichten HTML

## Technische Grenze

Der Quellcode des bestehenden Dienstes `project-evercade-deal-api.jnldc.chatgpt.site` liegt nicht in einem über GitHub zugänglichen Repository. Deshalb kann 0.9.4 den dortigen Worker nicht serverseitig neu deployen. GenericParser wird aus der Evercade-Anwendung aufgerufen und nach jedem Serverstatus wieder in den gemeinsamen Zustand eingemischt.

Ein wirklich unbeaufsichtigter Kleinanzeigen-Lauf bei vollständig geschlossener Webseite erfordert später Zugriff auf den Quellcode oder das Deployment des bestehenden Hintergrunddienstes.
